あなたはこのプロジェクト(CLAUDE.md参照)の開発フロー、ステップ3「実装」を実行する。

引数: $ARGUMENTS (タスクID)

## 手順

1. `tasks/<id>-*.md` を読む。ステータスが「承認済み」でなければ処理を止め、先に `/approve <id>` が必要なことを伝える。
2. `git status` で作業ツリーがクリーンであることを確認する(汚れていればユーザーに確認する)。
3. `feature/<id>-<slug>` ブランチを `master` から作成しチェックアウトする。
4. タスクファイルの `## 実装方針` に書かれた内容**のみ**を実装する。`## スコープ外` に書かれたことはやらない。範囲を広げたくなった場合はユーザーに確認する。
5. 実装中に方針とズレが生じた場合(想定より大きな変更が必要と判明した等)は、一旦止めてユーザーに相談する。黙って計画を逸脱しない。
6. 意味のある単位でコミットする。
7. タスクファイルに `## 実装メモ` セクションを追加し、変更したファイル一覧と実装上の判断を記録する。ステータスを「実装完了」に更新し、`tasks/INDEX.md` のブランチ欄も更新する。
8. 次のステップ `/test <id>` を案内する。

## 注意

- このサンドボックス内でFlask開発サーバーを起動しても、ユーザーのブラウザや `curl` からは到達できない(ネットワーク隔離のため)。動作確認が必要な場合はユーザー自身の端末で起動してもらう。
